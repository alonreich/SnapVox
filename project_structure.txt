SnapVox v3.0 - "The Ghost" Reality Map (Avalonia + ImageSharp Edition)
================================================================================

SYNCHRONIZED BRANCHES MANDATE
----------------------------
CRITICAL: The software is maintained as two functional branches from a SINGLE codebase:
1. Branch 1: Native (Windows OCR Engine, zero OCR dependencies).
2. Branch 2: Compiled with bundled Tesseract external OCR engine (LTS/Offline).

ENGINEERING STANDARD:
Every change (UI, logic, timers, overlay effects, editing tools) MUST be applied to both branches simultaneously.
Agents MUST ensure that features remain 100% synchronized between branches, except for the underlying OCR engine implementation itself.
Both branches utilize the high-performance SixLabors.ImageSharp pipeline for image manipulation and OCR pre-processing.

GOAL & PURPOSE
--------------
SnapVox is a professional-grade, ultra-fast screen capture and OCR tool optimized for .NET 9 Native AOT in the Windows OCR branch.
It serves users who need rapid imaging workflows with 100% privacy (zero cloud dependencies).
The application follows a "Ghost" philosophy: it stays out of sight until triggered, performs tasks with sub-millisecond responsiveness, and stays fully local. The Native branch is dependency-free for OCR; the Tesseract branch bundles local external OCR files.

CORE MANDATES (THE "GHOST" RULES)
---------------------------------
1. **Zero UI Friction:** Tray icon click triggers capture immediately. No splash screens.
2. **Avalonia/ImageSharp Runtime Path:** The active UI and image pipeline is Avalonia UI + SixLabors.ImageSharp; legacy compatibility names and shims may remain for migration support.
3. **SVG Toolbar UI:** The Editor uses bundled SVG toolbar icons and standard text/icon controls.
4. **Thin-Client Interop:** Use direct Win32 P/Invoke calls (snapvox.native.PInvoke) for performance, bypassing "heavy" .NET wrappers.
5. **Native Finality:** Branch 1 is compiled to machine code via .NET 9 Native AOT. Branch 2 uses a Native AOT installer wrapper with a self-contained non-AOT Tesseract payload because the external OCR runtime is not Native AOT-compatible.
6. **Async Everything (Engine Audit Parity):** All I/O, OCR, and cleanup operations MUST be non-blocking. 
   - No `Thread.Sleep`. Use `Task.Delay`.
   - No `.Result` or `.Wait()`. Use `await` or `IAsyncDisposable` / `DisposeAsync`.
   - Both OCR engines must validate required language packs (EN/HE) before execution.
7. **One-Click Sequential Finality (Zero Prompts):** The editor core is "Zero-Dialog". Only the following three actions trigger the blinking visual overlay before automatically closing the editor window. The close wait derives from the SAME configured blink duration as the overlay (NotificationOverlayDurationMs, clamped to 250-1000ms), so overlay and editor never drift: short settings end snappy, long settings let the overlay finish alone after the editor is gone:
   - "Save Image" (Ctrl+S): Saves 100% quality JPG to user's `Downloads` folder, copies to clipboard, and, when backup is enabled, saves a 24-hour JPG backup to `%TMP%\SnapVox\`.
   - "Copy to Clipboard" (Ctrl+C): Copies `CF_DIB` to clipboard and, when backup is enabled, saves a 100% quality JPG backup to `%TMP%\SnapVox\`.
   - "OCR": Copies text to clipboard and, when backup is enabled, saves `.txt` to `%TMP%\SnapVox\` and opens it in Notepad.
   - **Soft-Fail Fallback:** If the `Downloads` folder is missing/unwritable, popup a folder selection dialog ONCE, memorize the choice, and resume zero-prompt behavior for all future saves.
8. **Hardcoded JPG-Only Output:**
   - PNG ingestion is allowed (opening files or injecting from clipboard).
   - ALL image output (manual saves, 24-hour backup, automated history) is ALWAYS `.jpg`. 
   - Quality is ALWAYS 100%. No quality dialogs.
9. **Automated 24-Hour Retention:**
   - **Immediate Raw Backup:** When backup is enabled, every capture (region, full, window) immediately saves a raw 100% quality JPG to `%TMP%\SnapVox\` before any editing begins.
   - All enabled backup artifacts (images, text) purged from `%TMP%\SnapVox\` after 24 hours.
   - Cleanup task runs on startup and every 4 hours to purge the `%TMP%\SnapVox\` directory of expired files.
10. **Folder Structure Mandates:**
   - Persistent Install: `C:\Program Files\SnapVox\`
   - Persistent Logs: `%PROGRAMDATA%\SnapVox\`
   - User Config: `%AppData%\SnapVox\`
   - Local App Data: `%LocalAppData%\SnapVox\`
   - **Unified Temporary Root:** `%TMP%\SnapVox\`
     - All user-initiated saves, background snapshots, and OCR outputs MUST use this path for 24-hour retention.
     - Subfolder `\Lifecycle\`: Used for installer unpacking and self-cleanup.
     - Subfolder `\Runtime\`: Used for transient DLL extraction.
   - **Installation Log:** Saved EXCLUSIVELY to a standalone file at `%TMP%\SnapVox_Installation.log`.
11. **Visual Notification Overlays:**
   - Any successful download or OCR action MUST trigger a **blinking 4-color high-contrast overlay** (#FFFFFF, #FF3355, #00D2FF, #FFB703) honoring configurable duration (NotificationOverlayDurationMs in INI, clamped 250-10000ms, default 1.0s / 4 cycles).
   - Text variants: "IMAGE SAVED TO DOWNLOADS", "IMAGE SAVED TO CLIPBOARD", "TEXT COPIED", and "TEXT COPIED & SAVED".

UI/UX ACCESSIBILITY & LAYOUT MANDATES
-------------------------------------
1. **Named For Assistive Tech:** Every interactive control carries `AutomationProperties.Name`. Icon-only buttons must never ship unnamed.
2. **Minimum Target Size:** No interactive control is smaller than 24x24 (`SnapVoxMinTouchTarget`), per WCAG 2.2 SC 2.5.8.
3. **Single Dialog Implementation:** All confirmations go through `snapvox.editor.helpers.ConfirmDialog` - design-system colours, Escape to cancel, focus starting on the safe option. In-window prompts must disable the content behind them and move focus inside.
4. **Destructive Actions Confirm:** Clear All, Reset All Hotkeys and discarding unsaved Settings or editor changes all confirm first, stating what is lost.
5. **Tokens Only:** Colours, fonts and sizes come from `DesignSystem.axaml`. Brush properties bind to `*Brush` keys, never to `*Color` keys. No literal hex in window markup.
6. **Elastic Layout:** Labels, inputs and buttons use `MinWidth`/`MinHeight`, never fixed `Width`/`Height`, so DPI scaling and longer strings cannot clip text. Every resizable window declares `MinWidth`/`MinHeight`.
7. **RTL Ready:** Every window calls `UiLayoutDirection.Apply(this)`, which mirrors the chrome when `CoreConfiguration.Language` is a right-to-left locale. String translation still requires `language_*.xml` catalogues for `snapvox.foundation.core.Language`; none ship today, so the chrome is English-only until they are authored.
8. **One Icon, One Meaning:** No icon asset is reused for two different actions, and icons within a row share one size (24px in toolbars, 16px in the tray).
9. **LOCKED UI SPECIFICATION - PERMANENT AND IMMUTABLE - DO NOT ALTER (Line Thickness Quick Buttons Geometry):** The bottom pane quick line thickness buttons in `ThicknessChoicesPanel` are permanently locked to exact button widths: Tag 1 = 10px, Tag 2 = 11px, Tag 3 = 12px, Tag 5 = 15px, Tag 8 = 18px, Tag 12 = 22px, Tag 16 = 26px, with `Margin="0"`, `Spacing="0"`, and `FlowDirection="LeftToRight"`. This geometry provides a human-eye symmetrical progression. Modifying, recalculating, or tampering with these dimensions or spacing is strictly prohibited for all AI agents and developers.

TELEMETRY & LOGGING MANDATE (SINGLE SOURCE OF TRUTH)
----------------------------------------------------
1. **Comprehensive User Action Audit:** User interactions are captured by the application logger. Internal `ExecutionTrace` diagnostics may record thread id, memory, GDI/USER counts, queue depth, and elapsed timing for local troubleshooting.
2. **Recorded Events:** Screenshot coordinates, keyboard keys pressed, action cancellations, editor initializations, picture saves/downloads, and precise shape/object placements (including X/Y canvas coordinates).
3. **Success/Fail Finality:** Every logged action must culminate in a clear `[SUCCESS]` or `[FAIL]` status. Failures must include explicit, detailed exception data identifying the root cause. This log operates as the absolute single source of truth for all troubleshooting.
4. **Build Logging Tracking:** Compilation execution and output MUST be tracked via a `.\build.log` file at the repository root.

DEPLOYMENT & PACKAGING MANDATES (CRITICAL)
------------------------------------------
1. **Single-File Installer:** The deployment output for EACH branch MUST be a single `.exe` installer file. Branch 1 is Native AOT end-to-end; Branch 2 is a Native AOT installer wrapper containing a self-contained Tesseract payload.
2. **DLL Persistence:** Any extracted permanent `.dll` dependencies MUST reside exclusively in `C:\Program Files\SnapVox\`.
3. **Unpacked Persistence:** When the single `.exe` installer is run, it MUST unpack its payload into: `C:\Program Files\SnapVox\`

FUNCTIONAL SPECIFICATIONS (THE USER EXPERIENCE)
-----------------------------------------------
1. **Hotkey Triggers:**
   - `PrintScreen`: Starts custom rubberband region selection.
   - `Alt + PrintScreen`: Captures EXACTLY the current active window/app size only.
   - `Ctrl + PrintScreen`: Captures the entire virtual desktop / fullscreen.
   - `Shift + PrintScreen`: Repeats capture of the last selected region.
   - **High-Compatibility Copy:** Every capture is AUTOMATICALLY pushed to the clipboard as raw `CF_DIB` data for seamless pasting.
2. **Visual Feedback & Collision Mechanics:**
   - Systray Icon: Turns **RED** immediately upon entering capture mode. Returns to **BLUE** when finished.
   - **Intelligent Cursor Dodging:** On-screen instruction banners actively calculate bounding-box collisions and jump away from the mouse cursor to ensure the capture area is never obstructed.
3. **Unified Magnifier Engine:**
   - Shared circular UI style for both region selection and color sampler.
   - **Smart-Flip Region Selection:** Lens stays 30px diagonally away from cursor, "flipping" quadrants to avoid covering the capture area. 2x zoom.
   - **Color Sampler Magnifier:** Fixed-center logic with 8x zoom, live hex label, precise red crosshair, and full multi-monitor support.
4. **Magnetic Rubberband Snapping:**
   - Cursor over window triggers a high-visibility **Blue Highlight Border** snap with a strict **10-pixel proximity threshold**.
   - Initiating the rubberband selection directly on a window title area renders a dynamic "ghost effect" preview.
   - Coordinate accuracy is 100% DPI-aware, applying `RenderScaling` to logical Avalonia coordinates.
5. **OCR Painter Mode & Preemptive Caching (The "T" Toggle):** - Hitting `T` during selection toggles "OCR Painter" mode.
   - **Preemptive Background Execution:** Toggling the mode instantly triggers silent OCR across the entire virtual desktop before the region is drawn, guaranteeing zero-latency text extraction upon selection release.
6. **In-Editor OCR:** Clicking OCR symbol extracts text, copies to clipboard, opens Notepad, and saves `.txt` to `%TMP%\SnapVox\`.
7. **Intelligent Editor Display:** Implements parallelSniplets, Cascading Positioning, Majority Monitor Centering, and Adaptive Sizing to ensure non-overlapping, context-aware window placement across multiple displays.
8. **Save Workflow (single vocabulary):** The action is named "Save" everywhere - button, tooltip, Settings and accessibility name; only the completion overlay names the destination ("IMAGE SAVED TO DOWNLOADS"). Clicking "Save" writes a 100% JPG to `Downloads`, copies to Clipboard as `CF_DIB`, saves a temp backup only when backup is enabled, shows the overlay, and closes the window sequentially. Canvas items are called "objects" in every surface (tooltip, confirmation, delete button).
9. **Shell "Open With" Integration (Secondary Instance Routing):** Right-clicking any image format in File Explorer and choosing "Open with SnapVox" launches the Editor directly, bypassing Tray Icon initialization. All outputs from this workflow will be strictly saved/converted to `.jpg`.

Fix: every early-exit in CaptureHelper (and the exception fallback) now calls EndCaptureSession; CaptureWindow.OnClosed re-arms it if !_captureCompleted, and the ISSUE_005 overlay-close wait bounds the final release.

Sluggish Final Action / Overlay-Editor Drift (root cause): OnDownloadClick/OnCopyClick/OCR awaited a HARDCODED Task.Delay(1000) before closing the editor while the blink overlay honoured NotificationOverlayDurationMs - at a 500ms setting the editor idled 500ms after the blink was already gone, and long settings left the overlay blinking alone long after the editor closed. 16. Mixed-DPI Cross-Monitor Rubberband (root cause): snapvox.manifest opts into PerMonitorV2, under which EVERY top-level window carries exactly ONE DPI factor (the monitor that owns it), so the single virtual-desktop overlay from fix #7 could only map DIPs to device pixels correctly on its owning monitor - on mixed-DPI setups the rubberband was pixel-exact only on the screen where the drag started and drifted off the cursor or vanished on the other screen(s). Fix: CaptureRegionAsync slices the unified frozen backdrop per monitor and spawns one CaptureWindow PER MONITOR (each window lives entirely inside a single screen, so its DPI factor is exact), while CaptureWindow keeps the selection state in ABSOLUTE device pixels and broadcasts the rubberband + dimension badge, snap highlight + badge, alignment guides and magnifier ownership to the sibling overlays (ForEachOtherOverlay/ApplyShared*), each converting through its own Position/Scaling. The drag owner retains Win32 mouse capture across borders, the lens hands over to whichever monitor is under the cursor, the snap state is mirrored everywhere so C-copy works from any overlay, and leaving the snap zone mid-drag now clears the stale highlight.

 18. Editor Magnet Unreleasable While Resizing (root cause): the resize handles snapped the dragged edge to EVERY other shape's edges plus the image borders using the same wide 12-DIP capture zone as whole-shape moves - while enlarging, the dragged edge sweeps across many such targets, so escaping one capture (dragging 12 DIPs past it) dropped the edge straight into the next target's zone, which felt impossible to override mid-drag. Fix: resize handles now use a tighter 6-DIP capture zone (half the move zone, so an escape takes half the pull), and holding ALT is a LIVE magnet override on every snap path - resizing handles, dragging whole shapes, stretching new shapes and dragging line/arrow endpoints all follow the pointer raw while ALT is held and re-engage snapping the moment it is released (Shift's strict-angle mode still wins for vectors). The snap-dot indicator also hides while ALT is held so it never advertises a snap that is being overridden.
 19. Region Capture Crashing With InvalidCastException (root cause, introduced by fix 16): the per-monitor overlay rewrite cloned the unified frozen backdrop with a hard (Image<Rgba32>) cast - but NativeCapture produces Image<Bgra32>, and casting one closed generic to another compiles fine (both derive from the non-generic Image base) yet ALWAYS throws InvalidCastException at runtime, killing every region capture ~50ms in (log: "CaptureRegion failed." / Arg_InvalidCastException) before any overlay appeared. Captures had been broken on the shipped builds since fix 16 shipped. Fix: the clone now goes through Image.CloneAs<Rgba32>(), which performs a real Bgra32->Rgba32 pixel conversion and returns a genuine Image<Rgba32> - the same conversion pattern OcrImagePreprocessor already uses safely.

Resize Magnet Still Trapping Without ALT (root cause left by fix 18): the fix 18 resize snap computed each frame's magnet from the shape's ALREADY-SNAPPED bounds (left/oldW read back from the control after the previous snap), so every snap shifted the baseline - the effective capture zone stretched past the pointer, on release the edge jumped ahead of the cursor, and crossing back re-captured, chaining into an unreleasable loop only ALT could break; there were also NO guide rails while resizing, so the pull was invisible and read as a stuck cursor. Fix: resizing now runs through the EXACT same engine as dragging/placing whole shapes - a raw, never-snapped bounds accumulator (_resizeUnsnappedLeft/Top/Width/Height, the resize twin of _dragUnsnappedLeft/Top) is advanced by the pointer deltas each frame (opposite edge anchored; at the 10-DIP floor the dragged edge simply freezes, no hysteresis), and only the APPLIED bounds get bent by the new ApplyResizeMagneticSnap: the dragged edge snaps to any edge-or-center rail of every other shape plus the image frame (the identical candidate set TrySnapAxis uses for moves), the pull is capped at the shared 12-DIP VectorSnapThreshold, it releases the instant the raw edge leaves the zone, and the same dashed guide rails as the move magnet appear so the snap is gentle yet FELT. ALT stays a live raw override, the toolbar magnet button (MagneticSnappingEnabled) remains the user-facing toggle, and double-pressing a handle still flips snapping for that drag. The orphaned SnapAxisEdge/GetMagneticSnapTargets helpers and the ResizeSnapThreshold const were removed.

Installer Conflict State-Guarded Semaphore Release (root cause & bugfix): Implemented the state-guarded bool lockAcquired synchronization pattern in DeploymentLifecycle.cs across RunInstallAsync and RunUninstallAsync. Root Cause: mutex.WaitOne(0) returns false when another installer/uninstaller instance holds the named lock, setting exit code 2.
